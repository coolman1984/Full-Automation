# سجل القرارات الهندسية

| المعرّف | القرار | السبب والنتيجة |
|---|---|---|
| 001 | واجهة محلية بين الوكيل والأدوات | حساب ونموذج الوكيل منفصلان عن أدوات التشغيل. الاتصال عبر الإدخال والإخراج القياسيين، ومنفذ كروم محلي |
| 002 | بايثون بالمكتبة القياسية وجسر ويندوز | أجهزة التشغيل تقدر تستخدم المكونات المتوفرة. واجهة ويندوز متخصصة، ومهام المتصفح قابلة لاختبار مستقل |
| 003 | وصف مهمة بمدخلات وبصمة | يشغّل المحرك الخطوات نفسها بمدخلات متغيرة، ويوقف المجدول إذا تغير التعريف الذي تم تسجيله |
| 004 | فحص كل الفروع قبل التشغيل | الخطوة اليدوية أو الوسيط الثابت غير الصالح ممكن يظهر بعد أثر جانبي. الفحص يمنع بدء الوصفة في الحالتين. حالة التطبيق والنتائج الفعلية تُفحص أثناء التنفيذ |
| 005 | سجل دائم ببيانات تشغيل محدودة | ملف قاعدة محلي يربط الخطوات بمحاولة واحدة ويحتفظ بالتوقيت والحالة ونوع الخطأ. محتوى الصفحة والحقول والمحادثة له مسارات مختلفة |
| 006 | مرجع أدوات مولّد ومهارات بمصدر واحد | يتبع الفهرس تعريفات المحرك. نسخة كودكس تتولد من مهارات كلود وفحص التوثيق يكشف الاختلاف |
| 007 | فصل اختبار ويندوز عن إثبات المتصفح | وجود ملف تنفيذي يثبت التجميع، وتجربة كروم تثبت مسار المتصفح. إثبات التحكم والجدولة يحتاج جلسة ويندوز مناسبة |
| 008 | مراقبة عرض كروم من داخل الصفحة | سكربت يُحقن لكل مستند جديد ويرسل عبر ربط CDP، فالخطوات تستمر بعد التنقل. التسجيل صريح وظاهر، والقيم السرية لا تخرج من الصفحة. الإجراء غير المفهوم يبقى خطوة يدوية بدل التخمين |

أضف قرارًا عندما يتغير حد أو شكل أو التزام طويل الأجل. اربط المراجعة بالدليل في [التحقق](../CAPABILITIES.md) أو [الدروس](LESSONS.md).
